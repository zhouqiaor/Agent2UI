## 二、Agent 框架选型对比

### 2.1 LangChain4j (Java/Kotlin LLM 框架)

| 维度 | 评估 |
|------|------|
| **最新版本** | 1.8.0+ |
| **核心能力** | 统一 API 对接 15+ LLM 提供商、RAG、Agent 编排、工具调用 |
| **Android 兼容** | ⚠️ 需特殊配置（Desugar JDK 11、依赖裁剪） |
| **内存占用** | 经优化可控制在 80MB 内（精简依赖） |
| **方法数** | 优化后 ~33K（原始 ~89K，需裁剪） |
| **适用场景** | 云端 LLM API 调用、RAG 流程、多模型切换 |

### 2.2 端侧 LLM 方案对比

| 方案 | 原理 | 优势 | 劣势 |
|------|------|------|------|
| **Ollama + Termux** | 在 Termux 中运行 Ollama 服务（端口 11434），App 通过 HTTP 调用 | 完整 Ollama 生态，支持 100+ 模型 | 需安装 Termux，非 Play Store 分发 |
| **Ollama Android 库** | 原生 Android 库内嵌推理引擎 | 无需外部 App，体验原生 | 社区维护中，模型选择有限 |
| **TensorFlow Lite** | Google 官方端侧推理框架 | 稳定、文档完善、NPU 加速 | 需模型转换，不直接支持对话式 LLM |
| **ML Kit (on-device)** | Google Play Services 驱动 | 无需下载模型、自动更新 | 功能有限（翻译、识别等），不通用 |
| **Koog** (JetBrains) | Kotlin 原生 Agent 框架 | 纯 Kotlin、结构化并发 | 较新，社区规模待发展 |

### 3.2 MVI 状态管理模式（A2UI 特有）

```kotlin
// 1. 定义 UI 状态（密封类，覆盖 Agent 全生命周期）
sealed interface AgentUiState {
    data object Idle : AgentUiState
    data class Initializing(val progress: Float) : AgentUiState
    data class Running(val thoughts: List<String>, val currentStep: Int) : AgentUiState
    data class WaitingForUser(val prompt: String) : AgentUiState
    data class Success(val result: AgentResult) : AgentUiState
    data class Error(val message: String, val recoverable: Boolean) : AgentUiState
}

// 2. 定义用户意图
sealed interface AgentIntent {
    data object StartAgent : AgentIntent
    data class SendUserInput(val input: String) : AgentIntent
    data object CancelAgent : AgentIntent
    data object Retry : AgentIntent
    data class NavigateTo(val key: NavKey) : AgentIntent
}

// 3. ViewModel 实现
@HiltViewModel
class AgentViewModel @Inject constructor(
    private val agentUseCase: RunAgentUseCase,
    savedStateHandle: SavedStateHandle
) : ViewModel() {

    val uiState: StateFlow<AgentUiState>
        field = MutableStateFlow(AgentUiState.Idle)

    val uiEvent: SharedFlow<AgentUiEvent>
        field = MutableSharedFlow(extraBufferCapacity = 1)

    fun onIntent(intent: AgentIntent) {
        when (intent) {
            AgentIntent.StartAgent -> runAgent()
            is AgentIntent.SendUserInput -> sendUserInput(intent.input)
            AgentIntent.CancelAgent -> cancelAgent()
            AgentIntent.Retry -> runAgent()
            is AgentIntent.NavigateTo -> navigate(intent.key)
        }
    }

    private fun runAgent() {
        viewModelScope.launch {
            uiState.update { AgentUiState.Initializing(0f) }
            agentUseCase.execute()
                .onStart { uiState.update { AgentUiState.Running(emptyList(), 0) } }
                .collect { step ->
                    uiState.update { state ->
                        when (state) {
                            is AgentUiState.Running -> state.copy(
                                thoughts = state.thoughts + step.thought,
                                currentStep = step.index
                            )
                            else -> AgentUiState.Running(listOf(step.thought), step.index)
                        }
                    }
                }
        }
    }
}
```

## 五、技术风险与挑战

### 5.1 高风险项

| 风险 | 影响 | 缓解策略 |
|------|------|---------|
| **LangChain4j Android 兼容性** | 方法数超限、JDK API 缺失、内存占用高 | 精简依赖 + Desugaring + 模块化引入 |
| **端侧 LLM 性能** | 模型响应慢（3B 模型 ~2-5s/请求）、设备发热 | 限制模型大小（≤3.8B）、NPU/GPU 加速、电量管理 |
| **Navigation 3 尚处 Alpha** | API 可能变更、社区资源有限 | 封装自定义 NavManager 抽象层、跟进更新日志 |
| **Agent 长时间运行** | 系统杀后台、进程被回收 | WorkManager + 前台服务 + 进程恢复机制 |
| **Streaming 响应** | LLM 流式输出状态管理复杂 | 使用 `StateFlow<List<ChatToken>>` 增量更新 + `derivedStateOf` 优化 |

### 5.2 中风险项

| 风险 | 影响 | 缓解策略 |
|------|------|---------|
| **Hilt 多模块配置复杂度** | 跨模块注入困难 | 严格遵循接口隔离 + `@Binds` 绑定 + `@TestInstallIn` 测试替换 |
| **Compose 稳定性** | 非 `@Stable` 类型导致频繁重组 | 编译器报告检查 + 数据类 `@Immutable` 标注 + `derivedStateOf` |
| **Room + Flow 大数据量** | UI 卡顿 | Paging 3 分页 + `flowOn(ioDispatcher)` + 合理索引 |
| **Coil 图片内存** | 大量图片 OOM | 合理 `memoryCachePolicy` + `diskCachePolicy` + 缩略图 |

## 七、总结

A2UI Android 应用开发的核心技术选型遵循以下原则：

1. **以 Compose 1.10 + Material 3 1.4 为 UI 基石**，利用 BOM 统一管理版本
2. **Navigation 3 作为导航方案**，采用 `NavKey` + `NavDisplay` 的状态驱动导航
3. **Hilt 2.57 实现依赖注入**，配合多模块 Clean Architecture
4. **LangChain4j 精简集成**用于云端 LLM 调用，Ollama Android 作为离线补充
5. **MVI 架构模式**管理 Agent 全生命周期状态
6. **性能优先**：编译器报告检查稳定性、`derivedStateOf` 优化派生计算、Baseline Profile 提升首帧速度

> ⚠️ **重要提示**：Navigation 3 目前仍处于 Alpha 阶段（1.0.0-alpha06），建议在项目中封装一层自定义导航管理器以隔离 API 变化风险。LangChain4j 的 Android 兼容性问题需要在项目初期尽早验证。
